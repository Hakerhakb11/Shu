# Навык: FastAPI Clean Architecture (Слоистая архитектура)

При работе с Python FastAPI приложениями вы **ОБЯЗАНЫ** строго соблюдать принципы слоистой архитектуры и писать чистый, поддерживаемый код.

## Основные принципы
1. **Разделение ответственности (SoC)**: Каждый слой имеет одну задачу и знает только о слоях, находящихся ниже него.
2. **Правило зависимостей**: Зависимости направлены внутрь. Доменный слой (Domain) ничего не знает о внешнем мире (никаких импортов FastAPI, Pydantic, SQLAlchemy).
3. **Чистый код**: Обязательные type hints, докстринги, осмысленные имена переменных и функции с одной зоной ответственности (SRP).

## Обязательная структура проекта
Всегда генерируйте или рефакторите код в соответствии с этой структурой:
app/
├── domain/             # Доменный слой: бизнес-логика и сущности (чистый Python)
│   └── models.py
├── application/        # Слой приложений: сценарии использования (Use Cases), оркестрация
│   └── services.py
├── infrastructure/     # Инфраструктурный слой: внешние зависимости (БД, API, репозитории)
│   └── repositories.py
├── presentation/       # Слой представления: HTTP (FastAPI роутеры, Pydantic DTO)
│   ├── schemas.py
│   └── routers.py
├── core/               # Ядро: настройки, Dependency Injection, глобальные исключения
│   └── dependencies.py
└── main.py             # Точка входа: инициализация FastAPI приложения

## Правила для каждого слоя

### 1. Доменный слой (`app/domain/`)
- **ЗАПРЕЩЕНО** импортировать фреймворки (нет `fastapi`, нет `pydantic`, нет БД-драйверов).
- Используйте стандартные `dataclasses` или обычные классы Python для сущностей.
- Содержит чистую бизнес-логику, value-объекты и доменные исключения.

### 2. Слой приложений (`app/application/`)
- Содержит сервисы / Use Cases (например, `UserService`, `OrderService`).
- Оркестрирует поток данных между доменом и инфраструктурой.
- Получает зависимости (например, репозитории) через внедрение зависимостей (конструктор).
- Вызывает доменные исключения, а не HTTP-исключения.

### 3. Инфраструктурный слой (`app/infrastructure/`)
- Реализует интерфейсы, определенные в доменном слое или слое приложений.
- Управляет подключениями к БД, внешним API, файловой системой.
- Репозитории живут здесь и возвращают/принимают строго доменные сущности (Domain entities).

### 4. Слой представления (`app/presentation/`)
- **ЕДИНСТВЕННЫЙ** слой, которому разрешено импортировать `fastapi` и `pydantic`.
- `schemas.py`: Pydantic-модели исключительно для DTO (Data Transfer Objects) запросов и ответов.
- `routers.py`: Определение `APIRouter` FastAPI.
- Роутеры **НЕ ДОЛЖНЫ** содержать бизнес-логику. Они только:
  1. Валидируют входные данные через Pydantic.
  2. Вызывают метод сервиса приложения (внедренного через `Depends`).
  3. Преобразуют доменную сущность в Response DTO.
  4. Возвращают ответ или выбрасывают `HTTPException`.

### 5. Ядро (`app/core/`)
- Конфигурация (например, `settings.py`).
- Провайдеры Dependency Injection (например, `get_user_service`).
- Глобальные обработчики исключений.

## Чек-лист перед генерацией кода
Перед выводом кода проверьте:
- [ ] Есть ли импорты фреймворков в слое `domain`? (Если да, удалите их).
- [ ] Попала ли бизнес-логика в `routers.py`? (Если да, перенесите её в `services.py`).
- [ ] Используются ли type hints для всех аргументов и возвращаемых значений?
- [ ] Используется ли Dependency Injection (`Depends`) для сервисов и репозиториев в роутерах?
- [ ] Используются ли модели Pydantic *только* в слое `presentation` для DTO?

## Пример поведения
Если пользователь просит: "Создай эндпоинт для регистрации пользователя"
Вы ОБЯЗАНЫ:
1. Создать/обновить `app/domain/models.py` с dataclass `User`.
2. Создать/обновить `app/infrastructure/repositories.py` с классом `UserRepository`.
3. Создать/обновить `app/application/services.py` с методом `UserService.register_user()`.
4. Создать/обновить `app/presentation/schemas.py` с `UserRegisterSchema` и `UserResponseSchema`.
5. Создать/обновить `app/presentation/routers.py` с эндпоинтом FastAPI, внедряя `UserService` через `Depends`.
6. Связать всё в `app/core/dependencies.py` и `app/main.py`.
