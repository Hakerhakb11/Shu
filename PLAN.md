# Сервис Авторизации
- База данных PostgreSQL.
Таблицы для пользователей и ролей (Админ, клиент, курьер).

- Эндпоинты для регистрации и логина с хэшированием паролей (Bcrypt).

- Генерирация RSA-ключей: создание пары ключей. Private key остается внутри этого сервиса для подписи токенов, Public key отдается в API Gateway.

- Выдача токена: При успешном входе сервис генерирует Access-токен (JWT) и Refresh-токен, который отдается в защищенной HttpOnly куке.

- Logout и Refresh endpoint: endpoint для обновления токенов и endpoint выхода из системы, которая отправляет ID аннулированного токена в Redis.

- Обработка ошибок если сервис упал или токен невалиден



# Сервис Маршрутизации API-Шлюз (API Gateway)
- Прописывают маршрутизацию: Настраивают правила, куда перенаправлять входящий трафик (запросы /auth/** отправляются в сервис авторизации, а /catalog/** — в сервис питонистов).

- проверка токенов: фильтр, который перехватывает каждый запрос. Шлюз берет публичный ключ RSA и сам мгновенно проверяет подпись JWT, не обращаясь к сервису авторизации.

- Подключают Redis: Добавляют проверку черного списка токенов, чтобы заблокированные юзеры не могли сделать запрос.

- Пробрасывают контекст пользователя: Если токен правильный, шлюз достает из него ID и роль пользователя, кладет их в обычные HTTP-заголовки (X-User-Id и X-User-Role) и отправляет запрос дальше во внутренний микросервис.

- Защищают систему: Настраивают ограничение количества запросов в секунду (Rate Limiting) через Redis и защиту от зависания упавших сервисов (Circuit Breaker).

- Публичные ручки (Доступны всем):
GET /catalog/items — получение списка товаров с пагинацией (страницами) и фильтрацией по категориям и цене (как минимум).

GET /catalog/items/{id} — получение подробной карточки конкретного товара.

DELETE /catalog/items/{id} — удаление.

при запросе в эти ручки Проверка: Проверяют заголовок X-User-Role: SELLER. Если там CLIENT — отдают ошибку 403.

# Сервис Корзины (Cart Service) — Временное хранение
- База данных Redis: Каждая корзина хранится в Redis под ключом cart:{user_id} в виде списка добавивших товаров и их количества.

- Обработка «удаленных» товаров в корзине
Если продавец его удалил или снял с продажи — при вызове GET /cart Сервис Корзины должен вернуть "Товар недоступен"

- Связь с каталогом: При запросе корзины сервис обращается к Каталогу, чтобы достать актуальные названия, фото и цены товаров.

- Эндпоинты корзины:

GET /cart — получить содержимое корзины текущего пользователя (сервис берёт user_id из заголовка X-User-Id).

POST /catalog/items/batch (или GET /catalog/items?ids=1,2,3), который принимает массив [10, 15, 42] и одним запросом возвращает информацию по этим 3 товарам.

POST /cart/items — добавить товар в корзину (или увеличить его количество).

DELETE /cart/items/{item_id} — уменьшить количество или удалить товар из корзины.

DELETE /cart — полностью очистить корзину (вызывается после успешного оформления заказа).
